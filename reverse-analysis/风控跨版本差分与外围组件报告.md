# 风控跨版本差分与外围组件报告

> 上游索引：[风控研究总览](风控研究总览.md)。本报告覆盖酷安三版本（15.9.0 / 16.5.1 / 16.6.1）的安全能力差分，以及三个外围组件：metasec（字节/Pangle 广告供应链）、libnesec（易盾保护壳）、及安全栈重组时间线。
> 证据等级沿用总览定义。方法学：NetHT 全部安全字符串为栈上逐字节构造 + 简单算术解码（自研 Capstone 栈字符串重建器 + 全密钥集群验证）；壳 DEX 虽为易盾壳但字符串池明文可读，可做字符串级时间线；跨版本差分另含壳 DEX 字符串池全集差分与 APK 条目级差分。

## 6. metasec（字节/Pangle 广告供应链）

### 6.1 来源归属与独立时间线（E3）

- 当前晚间会话 maps 中 0 个 pangle 映射：**Pangle/metasec 亦为懒加载**，仅当广告 SDK 初始化时映射。

### 6.2 Native 能力（E3，静态）

- **模块框架**：`MSModuleCreator::register_t` 注册模块 1/2/3/5/6 静态 + 模块 4 运行期懒注册（工厂受 init 期状态门控，语义 UNKNOWN）；模块分发 `module_by_id_get(N) → BLR vtable+0x28`。
- **root/Magisk 检测**（模块 2）：30 项路径表（/sbin/magisk64、/sbin/.magisk、/system/xbin/su、Superuser/SuperSU、KingRoot 等）+ `ps | grep adbd` 命令探针输出中搜 "root" → 字段 `root` 写入模块 2 序列化链。
- **自动化应用检测**：10 项风险应用目录表（Auto.js、触动精灵、按键精灵、触摸精灵、clicker 类）→ 标记 `cka`。
- **【新检测面】JNI vtable inline-hook 完整性探针**：取 JNIEnv vtable 的 FindClass(6)/GetMethodID(33)/GetStaticMethodID(113)/GetStringUTFChars(169)/RegisterNatives(215) 五个函数指针，经 `process_vm_readv` 直读各函数序言 4 字节与解码期望值比对——检测的是 **JNI vtable 的 inline hook 行为本身**（ART hook 框架常见手法），而非匹配特定工具名；不匹配经通用"发现记录"汇聚点（28 个调用者）进入序列化链。
- **本地探测**（socket 导入的实际用途）：本地端口 bind 探测（EADDRINUSE 记录事件）、向 127.0.0.1 发 `GET / HTTP/1.1` 的本地 HTTP 服务探测——**本地探测，非数据上行**（该库自身不做网络上传）。
- **设置键** `kDisableIpCollection`：门控模块 2 的 **IP 采集**（可由宿主配置关闭；Java 侧 SecConfig 同键闭环）。
- 本地风险库/设置/节流键：`mssdk_riskapp_db` / `mssdk_setting` / `last_rp_time`。
- 导出面：仅 `JNI_OnLoad` + MSModuleCreator/MSPBDataHelper，无任何 `Java_*` 导出（全部接口经 JNI_OnLoad 内 RegisterNatives 注册）。

## 8. 跨版本根因判定

按"client capability change / remote config change / server-side policy"三分框架：

1. **CLIENT_CAPABILITY_CHANGED = 成立（区间 (15.9.0, 16.5.1]）**：-3 第三方范围化采集、LSPosed 检测从路径法升级为 maps 内存特征、inline-max ART 参数探针、filepermisson/changedPackages/shizuku/frida 新增。**限制**：这些变化在 16.5.1 已全部到位（16.5.1==16.6.1）；若时间相关性落在 16.6.1 或之后，native 能力变化无法解释该增量。
2. **REMOTE_CONFIG_CHANGED = UNKNOWN**：NetHT 探针门已证库内不可翻转（远比"远程开关"更弱）；useDDI/PostToken 当前值已固化采集，但历史值无样本。
