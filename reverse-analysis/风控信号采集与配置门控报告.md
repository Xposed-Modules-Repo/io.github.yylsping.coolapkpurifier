```text

   注册探针调度器（一次性守卫 0x242628）；置初始化总门 byte_4C26C8
   ↓
探针调度器 0x2483A8（每个探针两道门：linker 级别检查 + config 字节门）
   ├─ 注入/环境探针组：LSPosed maps / zygisk ptrace / odex inline-max /
   │    smaps / fdinfo-mnt
   │    门构造默认全 OFF，库内无写入者 → 全部静默，不产出事件
   └─ 周期定时器注册（0x24FFD4）
        ├─ 1min 扫描电池（11 成员）

   → popen 解析（0x273B74）→ 内存缓存 ingest 门（0x277278）

   （队列侧：uid_match / changedPackages / mis 等并行采集面同样入队，
```

## 3. 注入/环境探针与门控矩阵

### 3.1 探针清单（全部为运行时解码的隐藏检测词）

| 探针 | 实现 | 检测内容 | 事件 | 配置门 |
|---|---|---|---|---|
| LSPosed maps 内容搜索 | 0x2B7AD0 | 打开 `/proc/self/maps` 定位 `dalvik-main` 区，复制最多 0xF0000 字节，解码搜索 `LSPosed` + 邻接 `is-top-app` | 2000/"dal" | cfg[808]，默认 **OFF** |
| Zygisk ptrace/fork | 0x29A16C | fork + `PTRACE_ATTACH`/wait/detach 行为探测，解码 `zygisk` | 2000 | cfg[825]，默认 **OFF** |
| ART 编译参数探针 | 0x294620 | 从 base.apk 定位 `oat/arm64|arm/base.odex`，等价 `strings | grep inline-max-code-units=0`（直接检测 ART Hook 兼容编译状态） | 2000/"odex" | vtable 对象门（非 config 字节） |
| smaps 页统计 | 0x298F98 | 跟踪 `libandroid_runtime.so` 映射的 `Shared_Clean:`/`Referenced:` 前后变化 | 2000 | cfg[821]，默认 **OFF** |
| framework JAR 挂载探针 | 0x298170 | 扫 `/proc/self/fd` 定位 `com.android*.jar`，读 `fdinfo` 的 `mnt_id:`，≥1001 判定挂载来源异常 | 2000/"mnt" | cfg[809]，默认 **OFF** |

广义环境采集（相邻面，证明多信号聚合设计）：loop/ext4 挂载识别、直接 syscall 与 libc wrapper 时延差、mprotect/mincore/kernel 行为、模拟器检查、root 路径表（`/apex/com.android.art/bin/su` 等）、`scrcpy-server.odex` 投屏检测、`shizuku`/`frida` 字符串片段。

### 3.2 调度与门控机制（E3）

```text
冷启动 → SDK init → netht_register_probe_scheduler_once（0x242628，一次性守卫）
  → 探针调度器 0x2483A8 注册进宿主胶水表 qword_4C2298+496
  → 顺序分发全部探针，每个探针入口两道门：
      ① netht_linker_level_check（0x2E9684）：linker 级别 ∉ {3,4,5} 才继续
      ② config 单例字节门（getter → LDRB [x0,#off]；0 则跳过）
```

### 3.3 门控不可翻转证明（E3，多重互证）

1. 配置单例全局指针仅被 getter（0x26173C）数据引用（init flag / alloc / ctor / store 四处）。
2. 全库每个 getter 调用点后 10 条指令内，寄存器索引式 `STRB` **0 命中**。
3. ioctl 分发器 0x24646C 全量反汇编（1673 条指令）**0 索引式写入**。
4. 字面偏移写门者全库仅构造器（0x197454 / 0x22E41C / 0x1C8A84 的同偏移写入逐一排除为栈缓冲/导入表误报）。
5. 配置应用通路的规范化函数 0x261D00 的写入白名单**不含** 788/800/808/809/821/823/825/840 等门偏移（见 §8.3）。

**结论：注入/环境探针门在构造时一次写入为默认 OFF，此后在本库内不可变。** "服务端远程翻转探针开关"假设失去客户端机制支撑；早期报告中"私有通道可翻转门"的表述不成立。

## 4. installedApk 采集链与精确入选谓词

### 4.1 E3 采集链

```text
pm list packages -f --show-versioncode -U -3     ← 仅第三方包（-3 后缀为 (15.9.0,16.5.1] 引入）
  → 0x273B74 popen 逐行解析（path/package/versionCode/UID → 112B 记录）
  → 0x277278 扩展为 288B 缓存项 + enrich（权限/组件/签名）
  → 0x276E54 快照缓存 → 0x2FA14C append 主循环
  → 0x1ECC00 序列化器读 +0x30/+0x38 → protobuf field 12（wire tag 0x62）
  → aebd security blob（eventType 6）→ getToken（见传输链报告）
```

缓存为**纯内存**（缓存子系统无任何文件 I/O）→ 每次冷启动首次 build 的 field 12 = 当时可见的全部第三方包（事实全量）。

### 4.2 精确入选谓词（伪代码，每个条件均有指令级证据）

```text
bool shouldAppendInstalledApk(record, cache, eventType, config, now) {
    // 阶段 0：进入缓存（被 collector 看到）—— ingest 门
    if (!config.bit11)                     return false;   // selector 11，cfg[300] 默认 2 >1 = ON
    if (throttled(id=20))                  return false;   // ingest 节流
    if (!config[712] && oom_score_adj > 0) return false;   // cfg[712] 默认 ON → 前台豁免
    if (cache_contains(upperHex(pm行路径)))  return false;  // 缓存 miss 才收
    // enrich 门：宿主自身包豁免大小检查；其余包 APK ≤ cfg[512]（默认 200 MiB）

    // 阶段 1：进入本次 snapshot
    // "gt 全量路径"：eventType==6 && ctx["gt"]==1 && cfg[788]
    //   cfg[788] 默认 0 且库内无写入者 → 结构性不可能；"gt" 实为每次 getToken 的调用计数
    snapshot = cache_all_nodes();           // 默认：全部缓存节点

    // 阶段 2：逐记录 append 判定
    foreach record in snapshot {
        if (record.flag281 != 0) continue;  // 已上报 → 跳过（进程内一次性）
        payload = packageName;
        if (config.bit22)  payload += 权限标注（9 项，见 §5）;
        if (label != "")   payload += "@@" + label;
        if (acts > cfg[784]) payload += "@@as:" + acts;   // cfg[784] 默认 10
        element = "$S_BF#A" + "{" + md5hex(payload) + "}" + payload;
        if (eventType == 8) {               // event 8 专属门
            if (config[624] || (有标注 && config[674])) append(element);
        } else append(element);             // 其余事件恒 append
    }

    // 阶段 3：构建后状态迁移（构建成功才 promotion）
    markAllSnapshotNodes(flag280 = 1);
    promoteAll(flag280 → flag281);          // 缓存链表无删除/清空者，+281 永不清零
    // → 默认路径下每个包在进程生命周期内至多进入 field 12 一次（严格增量）
}
```

### 4.3 服务器实际获得的内容

field 12 是 repeated string，元素为 ASCII 帧：

```text
element := "$S_BF#A" "{" <32 位小写 md5 hex> "}" <payload>
payload := 包名 [权限标注]* ["@@" label] ["@@as:" 组件计数]
```

| 内容 | 进入 field 12 | 说明 |
|---|---|---|
| 包名 | 是 | 核心标识 |
| 9 项敏感权限标注（`@@inject`、`@@writesec`、`@@bindacc`、`@@shizuku`、`@@mockloc`、`@@su and alert and readclop` 等） | 是（cfg bit22 门控，默认 ON） | 来自包信息解析的权限匹配 |
| 包 label、组件计数（acts） | 是（条件性） | |
| apkPath / UID / versionCode / 签名摘要 / 完整权限列表 / min-target SDK / 其余五项组件计数 | **否** | 仅存在于本地缓存记录，不进入该字段 |

**服务器经 field 12 实际只拿到：包名 + 敏感权限标注 + label + 可选组件计数。** 元素不含 Hook、文件或路径特征。

## 5. 并行采集面（同库、同队列）

| 采集面 | 内容 | 产出 | 门控（默认） |
|---|---|---|---|
| filePermisson（field 9） | 扫描**外置存储** `/storage/emulated/0/Android/data`（路径含零宽空格混淆），产出 {包目录名, st_mode} 对 | field 9 | cfg[840] = **OFF** |
| mis（type 2000） | append 循环内对外存 Android/data 做相邻 UID 扫描（[self−200, self+200] ∩ [10200, 10500]） | 2000/"mis" 事件 | cfg[823] = **OFF** |
| uid_match（type 7） | 共享 UID 异名 / 自名前缀但 UID 不同比对 | type 7 事件 | 每次 build |
| changedPackages | component-8 列表差集（卸载/变更检测） | 报告容器（事件 {3,10}） | 事件掩码 |

**宿主私有目录阴性结论（E3）**：libNetHTProtect 中 `opendir` 仅 3 个调用者，逐一反编译后不存在任何针对 `/data/data`、`/data/user/0`、宿主 `files/`、`cache/` 的枚举路径。模块私有文件（配置/缓存/日志/so）**没有任何已识别采集边**。`filePermisson` 的真实语义是外置存储目录名+权限位，而非宿主私有文件。

## 6. 周期扫描器电池

探针调度器同时注册 3 个周期定时器（间隔 = 60s × cfg[N]，E3）：

| 定时器 | 周期 | 默认 | 内容 |
|---|---|---|---|
| 扫描电池（0x250310，11 成员） | 60s × cfg[84] | **每 1 分钟** | 成员共性：节流 → 读记录注册表 → selector 检查 → 组装事件推入全局队列，部分含立即构建触发 |
| 大清扫（0x250410，16 成员） | 60s × cfg[88] | 30 分钟 | 顺序执行 16 个电池成员；cfg[678]（默认 0=关）且任一命中 → 立即构建 eventType 7 |
| 包缓存刷新（0x25057C） | 60s × cfg[132] | 10 分钟 | selector(11) + ctx 条件 → 增量包缓存 ingest（installedApk 通道的周期补充源） |

**black_module 扫描器（0x2A658，周期电池成员之一）**：

- 遍历记录注册表中类型 tag `0x4204F8CA` 的记录；跳过 `/data/app/*.apk` 常规安装路径；
- 对**非常规路径的 APK 文件**生成 `black_module` 安全事件；首次命中：立即触发 eventType 1 的安全数据构建、写 `/.hrecord…`、并经胶水表疑似 `exit(0)`；
- 富集引擎（0x24188）通过 JNI 隐藏 API `android.content.pm.PackageParser.parsePackage` 解析任意 APK——installedApk 的权限/组件标注可不依赖 pm 命令获得。

## 8. 命令批处理器与记录注册表

### 8.1 记录注册表结构

全局单例（holder 0x9FAE4 + 1896B 管理对象）；`key → 容器偏移` 映射器（0x9B83C）把约 40 个整型键映射到管理对象内的独立容器（每个键 = 独立注册表；扫描电池直接读取的 key 203695656 → +48 容器，40 字节步长记录）。

### 8.2 写入侧：三条路径全部汇聚于命令批处理器（0x30D808）

命令批处理器解析 payload 状态码，code 200 时遍历类型化命令：type 5 → 配置应用；type 9 → 记录插入（MD5 校验后解析含 "version" 字段的 JSON 记录插入）；type 14 → 其它操作。三条喂入路径（全部 E3）：

1. **ioctl selector 16（Java 注入）**：酷安侧可经 HTProtect wrapper 下发命令批/记录。
2. **本地伪装资源加载**（0x241D20，唯一调用者 = 探针调度器）：先试文件 `<前缀>/home_button_*.xml`，失败则读组件资产 **`assets/home_button_colorful3.xml`**（伪装名），尾部 16 字节 MD5 校验 → 解密 → 命令批应用。**实测设备上该文件不存在**（base.apk / Pangle 两组件 APK / app files 目录均无，E3 阴性）。
3. **跨注册表传播**（0x230BF8）：从键 1207439958 的注册表取 JSON，提取 "/v4/c" 键后应用。

### 8.3 配置应用通路的精确边界（探针门结论的最终核对）

配置命令应用（0x2617D0）+ 数值规范化（0x261D00）的写入集合实证：

- **可远程调节的旋钮**：扫描节奏（cfg[84]/[88]/[132]，钳制 [1,60] 分钟）、阈值/计数（cfg[792]/[804]/[836]/[416] 等）、installedApk 模式族（cfg[336]/[340]/[344] 钳制 {1..4}，默认 2；cfg[300]±数组逐元素钳到 2）、三个 map 字符串项的增删；
- **不可调**：探针门字节 788/800/808/809/821/823/825/840 **全部不在写入偏移集合内**。

**最终结论：服务端/宿主可远程调节的是"对既有信号打分/调度"的节奏与阈值，而不是采集器开关**——这与服务端策略模型完全相容。Java 侧 `HTProtectConfig`（channel/gameKey/host/getExtraData）只写入 ctx，与配置门无映射边。

## 9. OS 权限门实测（本设备）

三个独立信号一致（E2 强，静态 + 运行交叉）：

```text
root 视角：            pm list -3  → 111 个第三方包（含作者本人的多个自研模块）
酷安 UID 视角：        pm list -3  → 1 个第三方包（仅酷安自己）
系统状态：QUERY_ALL_PACKAGES = granted；
          ColorOS GET_INSTALLED_APPS = denied + AppOps "ignore"（用户拒绝，USER_FIXED）
```

NetHT collector 的 `pm list -3` 以应用自身 UID 执行 → **本设备上只枚举到宿主自己 → field 12 实际不含任何第三方包（含模块）**。酷安自身也会主动检查该权限并在可读应用过少时弹出提示（宿主 UI 直接证据）。

推论：
- **本设备**：应用列表通道关闭；剩余活跃输入面 = metasec（Pangle）+ 基础设备身份 + NetHT 周期扫描器（仅 NetHT 已加载会话）。
- **权限授予的 ROM**：通道全开，第三方包全集在每次冷启动首次 build 事实上全量上报（每包进程内一次）。
- 该差异解释了不同用户/设备暴露面的分歧可能；权限状态由 ROM 与用户决定，不是客户端版本决定的。

## 10. 采集面小结

1. NetHT 的注入/环境探针（唯一可能"看见"Hook 环境的通道）**默认 OFF 且库内不可翻转**——在该构建中结构性静默。
2. installedApk 通道默认 ON 但受 OS 权限门约束；本机只见宿主自己；field 12 内容仅包名+权限标注+label。
3. 周期扫描器默认活跃（每分钟），但输入由命令批数据驱动且本机伪装资源不存在。
4. 宿主私有目录枚举不存在；模块文件无采集边。
5. 因此本机 NetHT 通道的实际可用信号显著收窄——这是根因排序中 NetHT 相关假设降权、metasec 与服务端策略假设升权的直接依据。
